# UI and worker test audit

At `38332cb`, the two crates had **601 Rust tests in 46 files** (544 UI, 57 worker). Screening produced 104 candidate groups. Prior work accounted for 30. Of the **74 groups audited here, 3 should be deleted, 12 strengthened, 4 converted to properties and 55 kept**. The three proposed deletions each have a neighboring test that failed on the same mutation.

## Method

Issue #759 gives examples of files but no list of test names. I enumerated `#[test]` declarations and inline and external test modules, matched them to the native test list, and grouped tests by file and the behavior they claim to protect. Each test file appears in the verdicts or exclusions. The only test in selection_projection.rs was already replaced under #755. Candidates included one-line adapters, flag and callback assertions, tests that reproduce production logic in the fixture, and repeated example cases. Tests already exercising distinct I/O failures, persistence or asynchronous interleavings also served as controls. The group count reflects this screening of the current tree.

The baseline passed all 1,211 workspace tests. For each audit row I selected a specific edit, changed one expression or statement, and ran the named tests with exact libtest filters via `mise exec -- cargo test` against the affected package. Each edit was restored with `git checkout -- <file>` and checked against the original bytes before the next edit. All Cargo runs used the shared `pool-2` target. The 199 distinct tests in the verdict table were green before mutation.

A **caught** result gives the number of failing tests over the number selected. A **survived** result means every selected test passed with the edit present. Of the 74 edits, 58 caused a runtime test failure, 15 passed every selected test, and one triggered a compile-time rejection. The fake-backend recorder is test-only, so its result measures the fixture. The ticket trait test has a compiler diagnostic in place of a runtime result. The checks used the native headless harness. Browser event delivery, OS window events and rendered pixels were outside the experiment.
